## 2. 업체별 제작 방식 상세

### 2.1 아이스크림미디어 (i-Scream media)

- **대표 콘텐츠 형태**: 차시 단위 수업 콘텐츠(동영상, 인터랙티브, 이미지), 교과서 QR 연계 영상·애니메이션·게임형 학습, AR/VR/가상실험/360°/HTML 콘텐츠, PPT 게임·활동지·놀이수업 등 수업 보조자료
- **제작 방식**:
  - 2000년부터 24년간 축적한 **650만 건 교육 전용 멀티미디어 아카이브**를 재조합·재활용하는 자산 기반(asset-based) 제작 — 신규 콘텐츠도 기존 에셋 재사용률이 높은 구조 (추정)
  - **현직 교사 200여 명과 공동 제작**: 초등 3~4학년 수업 콘텐츠 5천여 건을 교사와 함께 제작, 5~6학년 수학·사회·과학 5천여 건 추가 제작. 교사가 학습안을 편집·공유하는 생태계 운영
  - 교과서(서책)와 디지털 자료를 1:1로 연결하는 구조(교과서 지면 → QR → 디지털 콘텐츠), 즉 **성취기준→교과서 단원→차시→콘텐츠**의 매핑 체계가 제작의 뼈대
- **AI 활용 제작(공식 발표)**: 5개 영역 — (1) LLM: 아이스크림S 평어(교사 코멘트) 생성, (2) 이미지 생성: 에듀뱅크에서 AI 이미지·클립아트 생성, (3) 사운드 생성: 콘텐츠 더빙·자동 자막·영어 발음 교정, (4) 이미지/영상 인식: 학습 집중도·감정 분석, (5) 동영상 생성: "5분 이내 애니메이션 생성"으로 콘텐츠 개발 효율화 목표
- 출처: https://www.i-screammedia.com/www/digital_edu_contents.html , https://www.i-screammedia.com/www/business_iscreams.html , https://www.i-screammedia.com/www/ai.html , https://www.i-screammedia.com/front/boardview.do?cmsDirPkid=31&cmsLocalPkid=0&bbsConfigFK=2&pkid=340

### 2.2 아이스크림에듀 (홈런)

- **대표 콘텐츠 형태**: 초등 자기주도학습 프로그램(교과 예습·복습), AI 튜터(버추얼 휴먼), 게이미피케이션 콘텐츠(P.I.E), 생성형 AI 글쓰기(AI 드림라이팅), 지식추적 기반 수학 문항 추천(수학의 세포들)
- **제작 방식**:
  - **AI생활기록부**: 하루 1,600만 건 학습 빅데이터 분석 → 맞춤 학습 계획. 콘텐츠 기획도 이 데이터에서 역산 (추정)
  - **AI 드림쌤**: 업계 최초 "100% 생성형 AI 제작" AI 튜터 — 교육 특화 sLLM + 학습 데이터 분석 + 버추얼 휴먼(외모·성격·스타일·움직임까지 생성형 AI로 구현). 남녀 각 2명, 총 4명 캐릭터 중 테스트로 매칭 → **캐릭터를 콘텐츠 IP이자 개인화 장치로 사용**
  - EBS 제휴 콘텐츠 수급 병행(자체 제작 + 제휴의 하이브리드)
- **시사점**: "튜터/캐릭터 레이어"와 "콘텐츠 레이어"를 분리해서, 캐릭터는 생성형 AI로 양산하고 학습 데이터로 개인화하는 구조

### 2.3 아이스캔디 (외주 개발 스튜디오)

- **대표 콘텐츠 형태**: 교육 콘텐츠 HTML5 인터랙션, 디자인, 애니메이션, 게임
- **제작 방식**: "분야별로 전문화된 팀"(디자인/애니메이션/HTML5 개발) 구성으로 발행사 발주 콘텐츠를 구현. Flash(FLASHBOOK) 콘텐츠의 HTML5 전환이 주력 포트폴리오 — 즉 **발행사(기획·원고·스토리보드) → 스튜디오(에셋·인터랙션 구현)**로 분업되는 국내 제작 생태계의 실행 계층
- **시사점**: 대형사도 인터랙티브 구현은 20명 규모 전문 스튜디오에 외주 — 기획(교육 전문성)과 구현(웹 기술)이 분리 가능한 공정이라는 증거. AI 파이프라인에서 "코드 생성 에이전트"가 대체하는 지점이 정확히 이 계층

### 2.4 에듀템 (AI 컴포넌트 벤더)

- **사업 방식**: 콘텐츠를 직접 만들지 않고, 음성인식·발음평가·문장교정·청킹 등 **교육 특화 AI 모듈(ELA Solution)**을 발행사 콘텐츠/AIDT에 탑재. 고객: LG CNS, 동아출판, 대교, 능률, YBM, 시원스쿨, 리딩게이트, 인천교육청, 대학 다수
- **시사점**: 국내 AIDT 생태계는 "발행사(교육과정·검정) + AI 벤더(평가 엔진) + 개발 스튜디오(구현)"의 3자 분업. AI 파이프라인 설계 시 평가/피드백 엔진을 콘텐츠와 분리된 재사용 모듈로 두는 것이 업계 표준 구조와 일치
- 출처: https://www.edutem.net/ , https://thevc.kr/edutem

### 2.10 AIDT 시대 제작 트렌드 (KERIS 가이드라인 포함)

- **KERIS 「AI 디지털교과서 개발 가이드라인」 핵심 요구사항**:
  - 2022 개정 교육과정(성취기준)에 근거한 콘텐츠 구성
  - 학습분석 결과에 따라 **느린 학습자→보충, 빠른 학습자→심화**로 분기하는 맞춤 학습 경로
  - **보편적 학습 설계(UDL)** 및 **웹 접근성(KWCAG)** 준수

- **EBS**: 6~7단계를 외주제작사 공모로 조달, IP(펭수)와 검수는 내부 유지

## 4. 성공 콘텐츠 품질 요소 체크리스트 (자동 검증 가능 형태)

학습설계 관점 22개 항목. 각 항목은 AI 파이프라인의 QA 게이트에서 정적 분석(DOM/텍스트 검사) 또는 LLM 판정으로 자동 검증 가능한 형태로 기술.

### A. 도입(훅) — 근거: 게이미피케이션 호기심 자극 전략, Malone 내재적 동기 이론
1. [ ] 첫 화면(도입 30초 내)에 호기심 유발 질문이 1개 이상 존재 (`hook.question` 비어있지 않음 + 물음표 포함)
2. [ ] 훅이 학습자 일상·경험과 연결된 소재를 사용 (LLM 판정: 학년 세계관 — 저학년은 가족·친구·장난감·영웅 등 직접 경험 소재)
3. [ ] 훅에 시각 요소(이미지/SVG/애니메이션) 1개 이상 동반
4. [ ] 학습목표가 학생 언어로 1문장 제시됨 (행동 동사 포함, 예: "~를 구할 수 있어요")

### B. 스토리텔링·세계관 — 근거: 스토리텔링 기반 학습 연구, 캐릭터 IP 관행(펭수, AI드림쌤)
5. [ ] 콘텐츠 전체를 관통하는 스토리 맥락(등장인물 또는 상황 설정)이 존재하며 도입~마무리에서 동일 세계관 유지 (LLM 판정)
6. [ ] 캐릭터(안내자/튜터 페르소나)가 1개 이상 존재하고 이름이 부여됨
7. [ ] 각 장면(scene) 전환에 서사적 연결이 있음 — 장면이 독립 슬라이드 나열이 아님 (LLM 판정)

### C. 상호작용 밀도 — 근거: 아이스캔디류 HTML5 인터랙션 표준, AIDT 대화형 요구
8. [ ] 학습자 입력을 요구하는 상호작용 요소가 3개 이상 (클릭/드래그/입력/슬라이더 등 이벤트 바인딩 카운트)
9. [ ] 연속 수동 시청(클릭 없는 진행) 구간이 60초를 넘지 않음 (장면당 상호작용 1개 이상)
10. [ ] 핵심 개념은 "보여주기"가 아니라 "조작해서 발견"하도록 설계됨 — 파라미터를 바꾸면 결과가 바뀌는 조작 가능 모델 1개 이상 (simulation/game 타입 필수)

### D. 피드백·게이미피케이션 — 근거: 피드백의 정보·동기화·강화 기능, 보상·레벨 설계 연구
11. [ ] 모든 문항/시도에 즉각 피드백 존재 (응답 후 1초 내 정오 표시 + 이유 설명)
12. [ ] 오답 피드백이 정답 노출이 아닌 힌트/재시도 유도로 구성 (최소 1회 재시도 허용)
13. [ ] 진행도 표시(프로그레스 바, 단계 표시) 존재
14. [ ] 보상 요소(점수/별/배지/칭찬 메시지) 1종 이상 존재, 완료 시 성취 요약 화면 존재
15. [ ] 난이도가 단계적으로 상승 (쉬운 성공 경험 → 도전, 첫 과제 정답률이 높게 설계) (LLM 판정)

### E. 학년 적합성 — 근거: KReaD 지수(어휘 1~10등급, 평균 문장 길이, 어려운 단어 비율)
16. [ ] 본문 텍스트의 학년 수준이 대상 학년 ±1 이내 (KReaD류 지표: 평균 문장 길이, 저빈도 어휘 비율로 산출)
17. [ ] 초등 저학년: 한 문장 15어절 이내, 화면당 텍스트 3문장 이내 (DOM 텍스트 검사)
18. [ ] 미정의 전문 용어 없음 — 새 용어는 첫 등장 시 즉시 풀이 제공 (LLM 판정)

### F. 접근성·기술 품질 — 근거: KERIS AIDT 가이드라인(UDL, 웹 접근성), 모바일 우선 관행
19. [ ] 터치 타겟 44px 이상, 모바일 뷰포트(375px)에서 가로 스크롤 없음 (자동 렌더 테스트)
20. [ ] 이미지에 대체 텍스트, 색상만으로 정보를 구분하지 않음 (정오 표시에 아이콘/텍스트 병행)
21. [ ] JS 에러 0건, 모든 상호작용이 마우스·터치 양쪽에서 동작 (헤드리스 브라우저 스모크 테스트)

### G. 분량·구조 — 근거: 차시 분량 표준(수업 40분, 자기주도 콘텐츠 15~25분 추정), 도입-전개-정리 구조
22. [ ] 예상 학습 시간이 대상에 적합 (초등 자기주도 기준 5~15분: 장면 수 × 평균 체류 + 문항 수 × 1분으로 추산) + 도입/전개(조작)/정리(퀴즈·요약) 3부 구조 충족

## 5. AI 자동 생성 파이프라인 설계 제언 (EduFlix 적용)

업계 파이프라인(3장)의 각 단계를 프롬프트 체인의 스테이지로 인코딩하고, 사람 검수 게이트를 자동 QA 게이트로 치환한다. 핵심 원칙: **업계가 "프로토타입 스토리보드 승인 후 전체 양산"하듯, 단계별 중간 산출물(JSON)을 검증한 뒤 다음 단계로 진행** — 한 번에 HTML을 뽑지 않는다.

### Stage 1. 기획 프롬프트 (= 교육과정 분석·성취기준 매핑)
- 입력: 과목, 학년, 주제, 학습자 관심사
- 출력(JSON): 성취기준 코드/문구, 학습목표(행동 동사), 선수 지식, 오개념 목록, 콘텐츠 타입(game/quiz/simulation...) 선택 근거
- 인코딩: 2022 개정 교육과정 성취기준을 참조 데이터(교과·학년별 JSON)로 시스템 프롬프트에 주입 — 발행사가 교과서 매핑표를 내재하듯
- 게이트: 성취기준 매핑 1개 이상, 학습목표-주제 정합(LLM 판정)

### Stage 2. 학습 설계 + 스토리보드 프롬프트 (= 차시 구조·원고·SB)
- 입력: Stage 1 JSON
- 출력(JSON): 장면 목록 — 각 장면에 {유형(hook/story/core/quiz/wrap), 서사, 대사/내레이션 원고, 상호작용 명세(무엇을 조작하면 무엇이 변하는지), 피드백 규칙(정답/오답/힌트), 예상 체류 시간}
- 인코딩: EduFlixEngine의 hook→story→core→quiz→wrap 구조를 스키마로 강제. 체크리스트 A·B·C·D 항목을 프롬프트 제약으로 명시("훅은 질문형", "장면당 상호작용 1개 이상", "오답 시 힌트 후 재시도")
- 게이트: 체크리스트 1~15 중 텍스트로 판정 가능한 항목을 LLM 심사(루브릭 채점, 기준 미달 시 자동 재생성)

### Stage 3. 에셋 명세 → 생성 (= 디자인 단계)
- 입력: 스토리보드 JSON
- 출력: 에셋 매니페스트 {id, 유형(character/diagram/bg/icon), 프롬프트, 스타일 태그} → 기존 공유 에셋(icons/diagrams/backgrounds) 우선 매칭, 미보유분만 Gemini 생성
- 인코딩: 아이스크림미디어의 "650만 건 아카이브 재사용 우선" 원칙 = EduFlix의 `public/contents/{icons,diagrams,backgrounds}` 재사용 우선 + 네이밍 규칙(`{type}-{description}-{YYYYMMDD}`) 유지. 캐릭터는 시리즈 간 재사용해 IP 일관성 확보(AI드림쌤·펭수 모델)
- 게이트: 에셋 스타일 일관성(동일 팔레트·톤), 필수 에셋 누락 0

### Stage 4. 코드 생성 (= HTML5 개발, 아이스캔디 계층의 대체)
- 입력: 스토리보드 JSON + 에셋 경로
- 출력: index.html / style.css / script.js / manifest.json (기존 템플릿·mobile.css·EduFlixEngine 패턴 준수)
- 인코딩: 상호작용 명세를 `interaction.onInit` 콜백으로 1:1 변환. 피드백 규칙을 퀴즈 엔진 설정으로 변환. 스토리보드에 없는 즉흥 생성 금지(스토리보드가 단일 진실 원천)

### Stage 5. QA 게이트 (= 검수/QA, 교사 파일럿의 자동화)
- 4장 체크리스트 22항목을 3계층으로 실행:
  1) **정적 검사**(스크립트): 상호작용 요소 수, 텍스트 분량, 문장 길이, alt 속성, manifest 스키마
  2) **동적 검사**(헤드리스 브라우저): JS 에러 0, 375px 렌더, 터치 타겟 크기, 정오 피드백 동작
  3) **LLM 심사관**(별도 컨텍스트): 세계관 일관성, 학년 어휘, 오개념 유발 여부, 훅 품질 — 루브릭 점수화, 임계 미달 항목만 해당 Stage로 반송(전체 재생성 아님)
- 배포 후: 클릭·완주율 데이터(기존 clickTracker/recommendations)를 Stage 1 기획 입력으로 환류 — 웅진·아이스크림에듀의 데이터 폐루프 모방

### 운영 원칙
- 단계 간 산출물은 전부 파일(JSON)로 저장해 재현·부분 재실행 가능하게(업계의 "SB 확정본" 관행)
- 평가·피드백 로직(발음평가·문항 채점류)은 콘텐츠와 분리된 공용 모듈로(에듀템 모델) — EduFlix에서는 공용 quiz 엔진/피드백 컴포넌트로 구현
