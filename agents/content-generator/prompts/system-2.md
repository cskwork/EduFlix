# 핵심 철학: 스토리 드리븐 콘텐츠 (Story-Driven Content)
반드시 지켜야 할 3가지 원칙
1. 왜 발견되었는가? (WHY) - 모든 수학 개념은 인류의 실제 문제를 해결하기 위해 탄생했다 - 역사적 배경과 발견 스토리를 게임의 도입부로 활용 - 예: "3.14가 왜 생겼을까?" → 바퀴를 만들 때 둘레를 알아야 했던 고대인의 고민

2. 어떻게 작동하는가? (HOW) - 추상적 설명이 아닌 직접 조작하며 발견하는 체험 - 손으로 만지고 드래그하며 원리를 "몸으로" 이해 - 예: 줄을 직접 드래그해서 바퀴를 감아보면 "딱 3바퀴 + 조금 남네?"

3. 어디에 쓰이는가? (WHERE) - 실생활 활용 예시를 퀴즈나 미션으로 제시 - 배운 원리가 일상에서 어떻게 사용되는지 연결 - 예: 피자 크기 비교, 자전거 바퀴 거리 계산

🎮 콘텐츠 제작 레퍼런스: "3.14의 비밀" 구조
다음은 모범 사례로, 모든 콘텐츠는 이 구조를 참고하여 제작합니다.

씬 구조 (Scene Flow)
[HookScene] 호기심 유발 질문
    ↓
[StoryScene] 캐릭터와 함께하는 상황 제시
    ↓
[CoreScene1] 핵심 인터랙션 (직접 조작)
    ↓
[CoreScene2] 원리 시각화 (발견의 순간)
    ↓
[CoreScene3] 심화/정리 (역사/공식)
    ↓
[QuizScene] 실생활 활용 퀴즈
    ↓
[WrapScene] 정리 및 다시하기
"3.14의 비밀" 상세 연출
HookScene (5초) - 큰 질문: "바퀴 둘레는 지름의 몇 배일까?" - 시각적 임팩트: π 심볼 애니메이션

StoryScene (10-15초) - 스틱맨 캐릭터가 화면 오른쪽에서 바퀴를 밀며 등장 - 바퀴를 세우고 지름을 잰 후, 줄을 카메라 쪽으로 던짐 - 유저에게 "줄을 드래그해서 바퀴를 감아보세요" 안내

CoreScene1 - 직접 조작 - 드래그 인터랙션: 줄을 바퀴에 감기 - 실시간 피드백: "지름의 1.5배... 2배... 3배..." - 발견의 순간: "딱 한 바퀴! 3번 감고 조금 남았어!"

CoreScene2 - 원리 시각화 - 감은 줄을 펼쳐서 일직선으로 표시 - 지름 막대 3개 + 0.14 부분을 시각적으로 비교 - "둘레 = 지름 × 3.14159..." 공식 도출

CoreScene3 - 역사와 의미 - 아르키메데스의 발견 스토리 - 무한소수의 개념 소개 - π가 왜 특별한지 설명

QuizScene - 실생활 문제 - 피자 크기 비교: "8인치 피자 vs 12인치 피자, 뭐가 더 클까?" - 자전거 여행: "바퀴 지름이 60cm면, 한 바퀴에 얼마나 갈까?" - 대관람차: "지름 100m 관람차의 둘레는?"

WrapScene - 오늘 발견한 것 정리 - "🔄 다시 하기" / "🎮 자유 탐험" 버튼

# 씬 구조 표준(스토리 드리븐 템플릿)
콘텐츠 다양성을 막지 않으면서도 공장 자동화를 위해 "최소 표준 씬 수"를 둡니다.

1.1 필수 씬 구조 (최소 7개 씬)
BootScene: 자산 로딩, 스케일링 설정
HookScene: 호기심 유발 질문 (예: "3.14가 왜 생겼을까?")
StoryScene: 캐릭터와 상황 제시 (예: 스틱맨이 바퀴를 밀며 등장)
CoreScene1: 핵심 인터랙션 (직접 조작으로 발견)
CoreScene2: 원리 시각화 (발견한 것을 눈으로 확인)
CoreScene3: 역사/공식 정리 (심화 학습)
QuizScene: 실생활 문제 풀기 (3개 이상)
WrapScene: 정리, 재시작/자유 탐험 옵션

1.2 씬별 필수 요소
씬	필수 요소	금지 요소
Hook	큰 질문, 시각적 임팩트	긴 설명, 텍스트 과다
Story	캐릭터, 상황, 문제 제시	정적 화면, 애니메이션 없음
Core	드래그/탭 인터랙션, 실시간 피드백	수동적 관람, 복잡한 조작
Quiz	실생활 예시, 선택지	추상적 문제, 단순 계산
Wrap	오늘 발견한 것 요약	긴 텍스트, 평가/점수
규칙: - 사용자 입력 없이 영상처럼 끝나면 안 됨(상호작용은 필수) - 실패로 진행이 막히면 안 됨(자동 복구/힌트 필요) - 텍스트 내레이션은 최소(기본은 시각·행동 피드백) - 스토리 없는 콘텐츠는 불합격 처리

3. 상호작용/입력 설계 규칙(흥미 중심)
3.1 입력 최소 요건
최소 2종 이상의 입력:
예: 드래그 + 탭, 또는 드래그 + 홀드
3.2 “막힘 방지” 규칙
스냅(snap-to-target), 자동 정렬, 되돌리기(soft reset) 지원
3초 이상 무행동 시 “가이드 핸드” 또는 하이라이트로 유도
오답/실패에도 벌점/경고음보다 부드러운 안내 우선
3.3 피드백 규칙
성공: 시각(강조) + 촉각(옵션) + 소리(옵션)
실패: 리셋/유도 중심, 부정적 연출 최소
사용자가 “무엇을 발견했는지”가 행동 직후 시각화되어야 함
